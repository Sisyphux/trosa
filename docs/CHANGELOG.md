## 日期：2026-09-12（PostgreSQL 正式运行契约收敛）

修改内容：为 `db.py`、`serve.py`、`app.py` 和部署入口建立并强制
`trosa-postgresql-v1`；正式运行要求 PostgreSQL DSN，正式 ping 暴露 backend/contract
健康字段；Sela Gateway 只接受正式 PostgreSQL 健康响应；更新 Mac/Windows 入口、发布健康门、
PostgreSQL 演练和当前架构文档。

为什么修改：历史入口和切库文档允许新开发者误把 SQLite 当作正式业务内核，存在启动第二个
writer、把 Sela 当本地业务账本或在旧服务上继续开发的风险。需要让唯一正式业务路径由代码
在初始化前拒绝错误配置，并让 Sela 只承担 Agent 执行与可靠性职责。

影响范围：正式启动、健康检查、远端发布检查、隔离开发入口和文档；SQLite 仍保留为显式
隔离开发/历史演练/批准恢复材料，不参与正式运行。未新增业务表、未执行正式数据迁移、未
修改 ECS 数据。

是否需要迁移：不需要新的数据迁移；若发布到 ECS，发布门会按当前迁移 ledger/schema contract
和备份规则执行既有 PostgreSQL 校验。

当前状态：已完成正式发布。Trosa 160 项 Python 回归（1 项按环境跳过）、Sela 15 项回归、
Python/JavaScript 静态检查、浏览器扩展回归和隔离 PostgreSQL 17 演练通过；ECS release
为 `auto-20260912083340-d1d6972`（包含功能收敛 commit `7535b79`），公网四字段健康门通过，生产 `verify_schema` 确认
0001–0029 全部通过，Sela readiness 已恢复。

## 日期：2026-09-12

修改内容：建立 `docs/SYSTEM_STATE.md` 作为系统当前状态唯一事实入口；建立本文件作为唯一架构变更日志；冻结文档职责表。

为什么修改：根目录 18 个 md 口径分裂（切库文档仍称 SQLite 为活动生产路径、设计标准仍称 SQLite 为唯一事实源），新人无法判断以谁为准；需要单一事实来源。

影响范围：全部后续架构/功能/权限修改的流程约束；不改业务代码与数据。

是否需要迁移：否（纯文档新增）。

当前状态：已生效。争议以 `docs/SYSTEM_STATE.md` 为准。

## 日期：2026-09-03（历史架构结论收录）

修改内容：正式业务写入源切换为 ECS 本机 PostgreSQL；SQLite 退为隔离开发/导入演练/明确批准回滚边界。

为什么修改：单机多用户需要真正的事务、外键/唯一约束与统一组织作用域；SQLite 多库分片无法承载。

影响范围：全部读写路径、备份恢复（PG dump+附件bundle）、发布检查。

是否需要迁移：是（已执行：SQLite 快照 → PG 导入 → dump/restore-check；回滚材料保留）。

当前状态：已完成（`POSTGRESQL_FINAL_CUTOVER_CHECKLIST.md` 为历史证据）。注意 `POSTGRESQL_PRODUCTION_CUTOVER.md` 仍保留切换前口径，已判定归档，不再作为现行文档。

## 日期：2026-09（历史架构结论收录，trosa_domain 边界）

修改内容：确立 `trosa_domain.py` 为 Interaction/Task 唯一业务写入通道；Today 与 Customer 共用同一排序；退役 outreach 调度行永不能转为待办（SQL 强制）。

为什么修改：此前同一事实多入口写入、同一事项两页排序不同、历史自动开发节点污染 Today。

影响范围：`app.py`、`gmail_sync.py`、Gateway/Agent 写入、Today/Customer/Inbox/Search 显示。

是否需要迁移：否（规则收敛，不改历史行；历史 outreach 行保留可查）。

当前状态：已生效。新增写入路径必须复用该通道，禁止第二条业务路径。

## 日期：2026-09（历史架构结论收录，Agent/Gateway 边界）

修改内容：上层 Agent 只经 `/api/agent/*`（登录会话原子读取+确认式提案）与 `/api/gateway/*`（个人 token+scope+幂等写入）访问；Sela 只经受限集成接口同步已确认外联；三方均不直连数据库。

为什么修改：防止 Agent 绕过身份匹配、幂等与人工确认，直接改写业务事实。

影响范围：Sela 同步、浏览器扩展、外部 Agent 集成。

是否需要迁移：否。

当前状态：已生效。详见 `AGENT_API_CAPABILITY_AUDIT.md`（原文归档备查，边界已并入 `docs/SYSTEM_STATE.md §6`）。
