# UI 质量基线

> 与风格无关、任何房间都必须满足的工程与体验底线。风格、材质、构图见 [`DESIGN_WORLD.md`](DESIGN_WORLD.md)。
> 本文由旧版 `archive/TRADE_OS_UI_SYSTEM.v1-warm-editorial.md` 中仍然成立的部分迁入并去掉了陶土色、玻璃、Command Shelf 等风格约束。“必须”为强约束，“应该”为默认。

## 1. Token 三层架构

正式样式采用三层，组件不直接写死颜色和尺寸：

1. **原始值（Primitive）**：色阶、像素值、透明度、时间。现行为 `--dl-*`（`app/static/visual-v3.css` `:root`）。
2. **语义值（Semantic）**：页面背景、正文、主操作、危险状态等角色，例如 `--surface-canvas`、`--text-primary`、`--action-primary`、`--status-danger`。
3. **组件值（Component）**：按钮背景、导航选中态等具体用途。

```css
--dl-ink: #24221d;                        /* 原始值 */
--action-primary: var(--dl-ink);          /* 语义值 */
--button-primary-bg: var(--action-primary); /* 组件值 */
```

组件不得直接引用原始色阶，除非该值本身就是该组件唯一的视觉资产。`visual-v3.css` 已把历史 token 家族（`--v2-*`、`--ui-*`、`--error-*` 等）统一映射到 `--dl-*`，新代码不要再新增别名家族。

**层级 Token**：`--z-base 0` · `--z-sticky 20` · `--z-menu 60` · `--z-overlay 80` · `--z-modal 100` · `--z-toast 120`（房间自有的浮层介于其间时先在此登记）。不得在组件里随意使用 999、9999。

## 2. 交互状态总则

所有可操作组件至少设计以下状态：

| 状态 | 视觉要求 | 行为要求 |
|---|---|---|
| 默认 | 清楚但不过度突出 | 可以理解用途 |
| 悬停 | 背景或明暗轻微变化 | 不产生布局位移；不依赖悬停获得必需信息 |
| 按下 | 明度轻微变化 | 反馈不超过 100ms |
| 键盘聚焦 | 2px 焦点环，外移 2px | 不被容器裁切 |
| 禁用 | 降低对比并保持可辨识 | 不响应点击；有原因时给出提示 |
| 加载 | 保持原尺寸 | 防止重复提交，文字说明正在发生什么 |
| 成功 | 短暂确认结果 | 随后回到正常层级 |
| 错误 | 危险色 + 文字说明 | 提供修正方法，不只显示错误代码 |

## 3. 状态完整性

核心页面与房间必须区分：**加载、空、未登录、权限、网络、服务、解析错误**。

- 无数据与加载失败必须有不同的文案和视觉；失败不得显示成“没有数据”。
- 网络或服务错误保留已加载内容并允许重试；需要用户处理的问题使用页面内反馈，不藏在短暂 Toast 里。
- 首次进入可用结构骨架（保持真实行高，不用全屏转圈）；局部刷新只加载对应区域。
- 空状态：说明这里是什么、为什么为空、下一步可以做什么；正文不超过两句，只给一个主要下一步。
- 未配置 AI 时功能完整可用；AI 生成中说明在分析什么，失败时保留用户输入。

## 4. 组件行为规则

### 按钮与文案
- 每个页面或弹层只有一个实心主要按钮；同一弹层不出现两个实心按钮。
- 文案写具体动作（“添加客户”“记录沟通”“保存修改”），不写“确定”“提交”。
- 加载时保持原宽度并写明“正在保存”；只有图标的按钮必须有可访问名称。

### 表单
- 标签始终可见，不用 placeholder 替代标签；placeholder 只给格式示例。
- 相关字段成组，非核心字段折叠为“更多资料”。
- 错误说明靠近字段并说明如何修正；错误状态不改变控件尺寸。
- 必填用文字“必填”或可访问说明，不单独依赖红色星号。
- 保存成功要说明结果，不只显示“成功”。

### 弹层与面板
- 简短确认用弹窗；需要阅读上下文或连续编辑时用侧面板或工作区。
- 标题、正文、操作区职责固定；正文很长时只滚动正文，标题和操作区保持可见。
- 关闭、取消、主操作的位置在全站一致。有未保存修改时，关闭必须进入明确的保留/放弃流程。
- 弹窗打开后焦点进入弹窗，关闭后回到触发位置；Escape 只关闭不会导致数据丢失的临时浮层。

### Toast
- 成功 3–4 秒，错误保留到用户关闭或问题解决；必须说明结果（如“客户已归档，可以在设置中恢复”）。
- 页面内容已明显变化时不重复显示无价值的“成功”。

### 列表与表格
- 客户、待办、时间线优先用连续列表；长文本单行截断，打开详情后必须能看到完整信息。
- 表格只在需要跨行比较固定字段时使用；数字右对齐、文本左对齐、日期格式一致；窄屏转换为列表或只保留关键列，不做无法阅读的横向压缩。
- 筛选变化保留滚动位置；结果为空时说明当前筛选条件。

## 5. 可读性与无障碍

- **对比度**：普通文字 ≥ 4.5:1，大文字 ≥ 3:1；玻璃或渐变之上的文字按其最复杂背景验证；焦点、错误、选中不能只用颜色表达。低对比只用于非必要装饰。
- **点击与键盘**：鼠标目标 ≥ 36×36px，触控目标 ≥ 44×44px（控件默认高度见 `--dl-tap`/`--dl-tap-touch`）；所有功能可通过键盘完成；Tab 顺序与视觉顺序一致。
- **缩放与系统设置**：浏览器 200% 缩放时核心操作可完成；支持系统减少动态和应用内性能模式；不依赖悬停才能看到必需信息；文本不嵌入位图，图标有可访问名称。
- **响应式基线**：宽屏增加留白与并列上下文，不无限拉长文字行（中文正文一行建议不超过 42 个汉字，长报告约 720px）；窄屏导航进入抽屉，表格转列表，操作区允许换行。

## 6. 内容呈现细节

- **日期与时间**：见 `DESIGN_WORLD.md` 1.7；相对时间只用于近期内容，详情里提供准确日期。
- **数字与统计**：统计只为帮助决策而出现，不以大块占据首屏；不做 KPI、排名和没有行动意义的红色数字。
- **长名称与多语言**：布局不能依赖固定字符数；中英文之间由字体系统自然处理，不手动加空格。
- **AI 内容**：必须标注“AI 建议”或“AI 分析”；事实依据优先显示；AI 长文本落在稳定的阅读面上；核心页面不等待 AI。

## 7. 视觉验收矩阵

### 必测窗口
| 场景 | 尺寸 |
|---|---|
| 大桌面 | 1440×900 或更大 |
| 普通笔记本 | 1280×800 |
| 窄桌面窗口 | 960×760 |
| 平板 / 窄屏 | 768×1024（iPad 另测触控） |
| 手机 | 390×844 |

另须覆盖：旧 Win10 浏览器、键盘全流程、200% 缩放、性能模式与减少动态。

### 必测数据状态
初次使用完全空白；正常数据；20 条以上列表；超长中英文客户名；没有联系人或没有下一步；多项逾期；加载中、局部失败和完整失败；权限不足、禁用操作、未配置 AI；弹窗有未保存内容。

### 截图要求
- 正式页面视觉修改保留修改前后截图，窗口尺寸、数据和滚动位置相同。
- 至少检查默认、选中、空状态和一个弹层；差异说明是预期改变还是回归。

## 8. 每次 UI 修改的自检

- 是否复用了已有 token 和共用词汇？新增的颜色、字号、圆角、阴影，理由是什么？（房间不得新增材质，见 `DESIGN_WORLD.md` 第 2 节）
- 屏幕上是否只有一个焦点和一个实心按钮？
- 状态（加载、空、未登录、权限、网络、服务、解析错误）是否完整，失败是否没有被显示成“没有数据”？
- 键盘、焦点、200% 缩放、减少动态是否可用？
- 长客户名、中英文混排、大量数据是否会破坏布局？
- 是否仍符合 `PRODUCT_DESIGN_STANDARD.md`，且没有破坏客户、联系人、沟通记录、Today、Inbox、Search、备份恢复或 Sela 幂等同步？
