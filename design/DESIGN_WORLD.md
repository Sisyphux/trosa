# Trosa 设计世界：Daylight + 房间

> 现行 UI 规范。结构是“**世界 + 房间**”：世界全站固定，房间每页可以完全不同。
> 事实来源：`app/static/visual-v3.css` 的 `:root`（`--dl-*`）与 `design/visual-exploration/workspace-v4/02-daylight.html`（含同目录 `README.md`）。文中数值若与代码不符，以代码为准并回来改本文。
> 与风格无关的可访问性、状态、组件行为和验收矩阵见 [`UI_QUALITY_BASELINE.md`](UI_QUALITY_BASELINE.md)。旧的暖质编辑式规范已归档到 [`archive/`](archive/TRADE_OS_UI_SYSTEM.v1-warm-editorial.md)，不再约束新设计。产品原则仍以 `PRODUCT_DESIGN_STANDARD.md` 为准。

## 1. 世界（全站固定）

### 1.1 光即注意力

一屏一个焦点：光落在“此刻该做的事”上，周边退到低对比。

- **一个焦点**：每个屏幕（页面或弹层）只有一处被点亮的内容，通常是“下一步”或当前选中项。
- **明暗差就是层级**：信息重要度用墨色深浅表达（`--dl-ink` → `-2` → `-3` → `--dl-mut`），不靠加框、加色、加徽章。
- **唯一实心元素**：整屏只有一个实心（`--dl-ink` 底）按钮，通常是“记录沟通”；其余动作是文字或描边。弹层是新的一屏，可以有自己的一个实心按钮；危险操作只在最后确认一步才用危险色实心。
- **金色只表达位置与顺序**：当前项、悬停、聚焦、下一步的日期与次序。金色不装饰，不表示“好/坏/类别”。
- **光会跟着注意力走**：精细指针设备上，`.daylight-room__pool` 以每帧 0.055 的插值缓慢跟随（“光比手慢一点”），悬停记录时移到该记录上。它是唯一允许的持续动效，因为它本身就是层级信息；触屏、减少动态、性能模式、页面隐藏时关闭，关闭后页面必须仍然完整可读。

### 1.2 材质与 Token

材质只有三种：**墙**（房间背景，带天光渐变）、**纸**（阅读面）、**墨**（文字与实心动作）。可以凭内容调整层次，不能新增材质。

| 类别 | Token（值以代码为准） | 用途 |
|---|---|---|
| 墙 | `--dl-hi #faf8f2` · `--dl-canvas #efeae0` · `--dl-canvas-low #ded6c6` | 房间由高到低的三个明度 |
| 纸 | `--dl-paper #fffdf7` · `-2 #fbf8f1` · `-3 #f5f1e7` | 主阅读面 / 次级面 / 凹陷底 |
| 墨 | `--dl-ink #24221d` · `-2 #57534a` · `-3 #6f6a5f` · `--dl-mut #8a8478` · `--dl-faint #b7b1a4` | 主文字与实心动作 / 次级 / 三级 / 仅限安静标签 / 仅限禁用与分隔 |
| 金 | `--dl-gold #bc9052` · `--dl-gold-ink #8a6224` · `--dl-gold-soft #f3e7d3` · `--dl-gold-wash` | 装饰与焦点环 / **纸面上的金色文字必须用 gold-ink** / 选中底 |
| 状态 | `--dl-danger #a4443a` · `--dl-ok #5c7a5a` · `--dl-info #4f6d78` · `--dl-warn #8a6a1f`（及 `-soft`） | 只表达状态，必须带文字 |
| 细线 | `--dl-hair .13` · `-2 .07` · `-strong .26` | 1px 细线取代边框和卡片 |
| 阴影 | `--dl-shadow-1…3`、`--dl-shadow-ink` | 纸是平的；只有临时层（菜单、弹层、浮层）才浮起 |
| 圆角 | `--dl-r-xs 6 · sm 9 · md 12 · lg 16 · xl 22 · pill` | 精确而不圆润 |

- 光晕、天光带（`sunband`）和光池（`pool`）属于“光”，不是材质：可以用渐变与模糊，但只能作为背景光，不承载文字和数据。
- 新代码只引用语义层或 `--dl-*`，不写死色值。三层 Token 结构见 `UI_QUALITY_BASELINE.md`。

### 1.3 字体与字阶

- **Newsreader**（衬线）只用于身份与焦点：页面标题、客户名、焦点句、读数数字。中文回退到清晰无衬线，不落到宋体/SimSun。变量 `--dl-display`。
- **Inter** 用于数据与正文，数字用等宽数字特性（`tabular-nums`）。变量 `--dl-sans`；`--dl-mono` 仅用于编号类内容。
- 根字号 15px（界面字号四档与性能模式整体缩放，不要写死 px）。

| 角色 | Token | 约合 |
|---|---|---|
| 页面标题 | `--dl-fs-hero` 2.5rem（窄屏 `-s` 2rem） | 37.5px |
| 焦点 / 区块主标题 | `--dl-fs-title` 1.28rem | 19px |
| 卡片标题 / 小标题 | `--dl-fs-h3` 1rem · `--dl-fs-h4` .9rem | 15 / 13.5px |
| 正文 / 次级正文 | `--dl-fs-body` .95rem · `-body-s` .86rem | 14.25 / 12.9px |
| 标签 / 说明 | `--dl-fs-label` .82rem · `--dl-fs-caption` .76rem | 12.3 / 11.4px |
| 结构小标 | `--dl-fs-micro` .66rem + 字距 `.18em` 大写 | 9.9px，只作结构装饰 |

结构小标（大写宽字距）只标注“这一块是什么”，其中的信息不能是用户必须读到的内容。

### 1.4 动效底线

- 框架不动，被聚焦的任务可以动。位移通常 ≤ 8px；列表变化保持位置连续。
- 时长用 `--dl-dur-fast .16s`（微交互）、`--dl-dur .28s`（面板、弹层）、`--dl-dur-slow .55s`（明暗过渡、光移动、转场）；缓动 `--dl-ease`。
- 动画只做四件事：说明来源、确认结果、保持连续、引导注意。
- 必须响应 `prefers-reduced-motion` 与应用内性能模式：动画直接到终态，功能不变。

### 1.5 可访问性底线

细则与验收见 `UI_QUALITY_BASELINE.md`，这里只列世界级底线：

- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1。**纸面**上阅读文字至少用 `--dl-ink-3`（5.3:1）；`--dl-mut`（3.65:1）只能放非必要的安静标签，`--dl-faint`（2.1:1）只用于禁用、占位和分隔。墙面上 `--dl-ink-3` 约 4.49:1，重要文字优先放纸面或用 `-2`。
- 键盘可完成全部功能，焦点环 2px、外移 2px（`:focus-visible`）。**已知缺口**：金色 `#bc9052` 在纸面上仅 2.85:1，低于焦点指示器 3:1 的要求，改焦点环颜色前需先用 gold-ink 或双环方案评估。
- 200% 缩放时核心操作可完成；不依赖悬停获得必需信息（光的悬停跟随只是增强）。
- 目标尺寸：控件高度 `--dl-tap` 40px（粗指针 `--dl-tap-touch` 48px），任何点击目标不小于 36px / 触控 44px。

### 1.6 状态完整性

每个核心页面和房间都要区分并呈现：**加载、空、未登录、权限、网络、服务、解析错误**。失败不得显示成“没有数据”。

- 失败用错误块：红色左规线 + 文字说明 + 重试，保留已加载内容。
- 空状态回答三件事：这里是什么、为什么为空、下一步可以做什么（正文不超过两句，只一个下一步）。
- 局部刷新只加载对应区域；核心页面不等待 AI、网站读取、邮箱验证或后台任务。未配置 AI 时页面必须完整可用。

### 1.7 内容规则

- 日期：“2026 年 9 月 29 日”或“9 月 29 日”；近期优先“逾期 1 天 / 今天 / 明天”，详情里给准确日期；同一页面不混用格式。
- 数字用等宽数字；0 不强调；异常数字必须带解释；不用红色数字制造没有行动意义的压力。
- 按钮写具体动作（“记录沟通”“保存修改”），不写“确定”“提交”。
- **AI 内容必须标注“AI 建议”或“AI 分析”**，事实依据在前；AI 只预填与提议，不自动创建客户、联系人、待办或商业承诺；生成失败时保留用户输入。
- 沟通记录可以没有下一步；待办必须同时有明确动作和日期。
- 公司名默认单行截断，详情中完整显示；邮箱、网址、长编号可安全换行。

### 1.8 默认不做什么

这些是 Daylight 的默认，不是教条；想突破的房间，需要在它的 `rooms/*.md` 里写明理由并通过缩略图测试。

- **不用 Emoji 当图标**：图标统一为线性 SVG 且带可访问名称；Emoji 在不同系统渲染不一致，也破坏墨与纸的质感。
- **不靠颜色单独表达状态**：色觉差异与灰度环境下信息会丢失，状态必须同时有文字或图标。
- **不做装饰性持续动效**：持续运动会争夺“光”的注意力；除 1.1 的光池外，动效只在有信息时出现。
- **不给普通内容加卡片和重阴影**：纸是平的，层级由明暗和 1px 细线承担；卡片只表达一个可独立理解的上下文。
- **不让 AI 输出无标注地混入事实**：用户必须能区分“记录了什么”和“建议什么”。

## 2. 房间（每页可不同）

**页面可以在空间模型、隐喻、构图、招牌交互上完全不同，但不得引入新材质（新色系、新字体家族、玻璃、重阴影）。** 房间之间的差异来自“怎么摆”，而不是“换一套皮”。

- 已有的例子：登录入口（Colonnade 柱廊，按真实用户注册表逐位进入）与客户工作区原型（Daylight 日光：安静的沟通列 + 光里的唯一焦点）是两种不同的房间，同属一栋楼。
- 现状提醒：生产目前继承了 Daylight 的**皮肤**（`visual-v3.css` 只改外观不改布局），尚未继承原型的**构图**。房间化是逐页做的，见第 4 节流程，不要一次改所有页面。
- 房间共用的词汇：纸面与细线、结构小标、焦点句、文字动作 + 一个实心按钮、读数、错误块与空状态。
- 每个房间的细节写在 `design/rooms/<页面>.md`，模板见 [`rooms/README.md`](rooms/README.md)。

### 2.1 新意预算

每个页面 = **一个**空间模型变化 + **一个**招牌交互 + **一个**“意料之外但有用”的细节，其余全部使用共用词汇。

- 高频操作（记录沟通、确认）保持最快路径；新意放在**定位、上下文、反馈**上，不放在“完成这件事需要几步”上。
- 招牌交互和意外细节都必须在键盘、触屏、减少动态下有等价的可用路径。
- 预算是上限而不是配额：某页没有合适的新意就不要硬加。

## 3. 验证

- **缩略图测试**：把所有页面缩小拼成一张图。每页应能被认作不同的房间，同时明显属于同一栋楼；若全都长得一样，房间化不足，若像不同产品，材质越界。
- **去 logo 自检**：遮掉 logo 与品牌名，页面是否仍不像通用 SaaS 后台？若像，说明构图仍是“列表 + 卡片 + 侧栏”的默认解。
- **创作与评审分离**：做原型的人不是评审的人；评审对照本文和该房间的 `rooms/*.md`，并按 `UI_QUALITY_BASELINE.md` 的矩阵在真实浏览器验收（宽屏、iPad、iPhone、旧 Win10、键盘、200% 缩放、性能模式）。

## 4. 流程

**探索 → 独立 HTML 原型 → 人选定 → 提炼 `rooms/<页面>.md` → 实现。**

1. 探索：同一页面出几个方向，放在 `design/visual-exploration/`（独立 HTML，不接入产品数据，不需要后端）。
2. 人选定：由人从原型里选，不由 Agent 自行定稿。
3. 提炼：把被选中原型的构图、交互与例外写成 `rooms/<页面>.md`。**规范跟着被选中的原型走**，不再先写规范再画页面。
4. 实现：复用现有端点和数据模型；不改变客户、联系人、沟通记录、Today、Inbox、Search、备份恢复或 Sela 幂等同步的行为。世界与房间冲突时，先改文档并说明理由，再改代码。
