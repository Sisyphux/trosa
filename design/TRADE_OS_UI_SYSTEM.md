> 状态：**视觉方向已经确认，第一轮全局视觉与信息架构已经应用到正式界面。** 第二版“今天”样板作为实施基线；后续逐页深化时继续保留现有功能，并分别完成 Windows 网页、iPad 和 iPhone 查看验收。

| 标记 | 含义 |

## 1. 设计命题

### 1.1 核心方向

**暖质编辑式工作台（Warm Editorial Workspace）**

Trade OS 应像一本经过认真编排、会主动帮助用户整理关系的工作簿：温暖、克制、有质感，同时保持现代工具的效率与精确。

它不是传统 CRM 后台，不是数据驾驶舱，也不是展示技术感的概念产品。

### 1.2 体验关键词

- 安静：不争夺注意力，不制造无意义的紧迫感。
- 温暖：使用自然的纸张色、墨色和低饱和陶土色。
- 编辑感：依靠字体、版式和内容层级建立气质。
- 精确：操作反馈清楚，日期、状态和责任不含糊。
- 有呼吸感：允许页面自然滚动，不强求一屏容纳全部信息。
- 有人文感：像可靠的业务助理，而不是数据库管理界面。

### 1.3 设计语言来源与职责

| 来源 | 借鉴内容 | 不照搬的内容 |
|---|---|---|
| Claude / Anthropic | 暖色、编辑式排版、人文气质 | 品牌宣传页式的大字号和留白 |
| Notion | 清晰结构、低干扰组件、内容优先 | 过度朴素、所有内容都像文档块 |
| Apple / iOS | 材质、层级、动效、触控反馈 | 全页面玻璃化、过度圆润 |
| Google | 状态完整、可用性、表单反馈 | 高饱和品牌色和标准 Material 外观 |
| 无印良品 / 日式设计 | 克制、自然色、留白和秩序 | 刻意复古或生活方式商品感 |
| 欧洲编辑设计 | 字体比例、精致细节、优雅节奏 | 为形式牺牲阅读效率 |

## 2. 不做什么

- 不使用 Emoji 作为正式图标、导航图标或状态图标。
- 不使用荧光色、大面积蓝紫渐变、发光边框和赛博科技视觉。
- 不用卡片包裹每一组内容；优先使用留白、对齐和文字层级。
- 不为普通内容添加悬浮、抬升或夸张阴影。
- 不用颜色区分所有业务类别；颜色只表达操作、状态和少量识别。
- 不把液态玻璃作为长文本、表格或客户记录的背景。
- 不为了“高级感”使用过低对比度文字。
- 不引入仅在单个页面使用的新按钮、圆角、阴影或间距。
- 不用弹跳、旋转、粒子、呼吸灯等装饰性动画。

## 3. 视觉架构

### 3.1 三层材质

1. **纸张层**：页面主体、列表、时间线和表单。稳定、温暖、适合阅读。
2. **墨迹层**：文字、图标、分隔和关键信息。建立秩序与清晰度。
3. **玻璃层**：导航、浮动工具、AI 助手、弹窗和临时操作。表达悬浮与上下文。

玻璃只用于“浮在内容之上的控制”，不用于承载主要内容。

### 3.2 页面层级

- 第一层：当前任务和主要内容。
- 第二层：帮助理解任务的上下文。
- 第三层：系统信息、统计、设置和辅助说明。

视觉强度必须与层级一致。统计数字不能比今天真正要做的事情更醒目。

颜色值在视觉样板确认后冻结。冻结后新增颜色必须先说明现有颜色为何无法承载。

### 4.2 使用比例

- 约 72%：暖白、纸色和墨色。
- 约 18%：灰褐中性色和分隔。
- 不超过 10%：陶土、苔绿、雾蓝、赭金和梅灰等低饱和强调色。

辅助色可以丰富节奏，但不能变成业务分类系统。颜色表达的是信息角色与临时状态，不要求用户记住一套“颜色等于客户类型”的规则。

### 4.3 状态色

- 逾期可以使用危险色文字，但不使用整行红色背景。
- 成功反馈短暂出现，完成后回归普通内容层级。
- AI 建议使用中性玻璃或纸色，不默认使用紫色。
- 状态必须同时有文字或图标，不能只靠颜色表达。
- 全局 Trade OS AI 入口与面板采用可读性优先的液态玻璃材质，允许在可视区域内自由拖动并记忆位置；快捷问题使用横向滑动条，页面主体不产生横向漂移。

## 5. 字体与排版

### 5.1 字体角色

- 中文与英文正文：本地托管 `Noto Sans SC Variable`（思源黑体同源字族），系统无衬线字体作为回退。
- 中文与英文展示标题：本地托管 `Noto Serif SC Variable`（思源宋体同源字族），只用于大标题和关键引语。
- 数字与日期：系统无衬线字体，使用等宽数字特性。

生产环境不依赖无法保证加载的网络字体。若引入字体文件，必须本地托管并检查授权和中文覆盖。

### 5.2 字号阶梯

| 角色 | 桌面字号 | 行高 | 字重 |
|---|---:|---:|---:|
| 页面标题 | 38px | 1.15 | 500 |
| 重点标题 | 27px | 1.25 | 500 |
| 区块标题 | 18px | 1.35 | 600 |
| 正文 | 16px | 1.65 | 400 |
| 紧凑正文 | 15px | 1.55 | 400/500 |
| 辅助文字 | 13px | 1.5 | 400/500 |
| 标签 | 12px | 1.3 | 600 |

页面标题可使用衬线字体；按钮、输入、列表和正文统一使用无衬线字体。

### 5.3 文本规则

- 中文正文一行建议不超过 42 个汉字；长报告正文最大宽度约 720px。
- 界面正文不使用全大写；英文短标签可使用小型大写，但字距需克制。
- 同一行最多有三个视觉字重。
- 次级信息通过字号和颜色后退，不使用斜体。

## 6. 间距与布局

### 6.1 间距阶梯

只使用：`4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 80px`。

- 控件内部：8–16px。
- 同组元素：8–12px。
- 相邻内容块：24–32px。
- 页面区块：40–64px。
- 页面顶部与左右安全区：32–48px。

### 6.2 页面宽度

- 主工作区最大宽度：1240px。
- 长文本最大宽度：720px。
- 表单最大宽度：640px。
- 小弹窗：440–520px。
- 工作区弹窗或侧面板：720–1120px。

宽屏增加留白与并列上下文，不无限拉长文字行。

### 6.3 响应式基线

- `≥ 1280px`：完整侧栏，主任务与上下文并列。
- `960–1279px`：窄侧栏或浮动导航，双栏按内容收缩。
- `720–959px`：主内容单列，次级面板下移。
- `< 720px`：导航抽屉，操作区允许换行，表格转换为列表。

## 7. 形状、边框和阴影

### 7.1 圆角

- `10px`：按钮、输入、小标签和列表选中态。
- `16px`：普通容器、日期格和小浮层。
- `24px`：导航玻璃、主要浮层和大弹窗。
- 胶囊圆角只用于短标签、筛选器和独立浮动操作。

### 7.2 边框

- 默认使用 1px 低对比度边框。
- 内容分组优先用留白和细分隔线。
- 不使用不同颜色的左侧粗边框表达普通状态。

### 7.3 阴影

- 纸张内容：无阴影或极弱阴影。
- 浮动玻璃：柔和的大范围阴影。
- 弹窗：允许更明显但不发黑的阴影。
- 普通卡片悬停时不抬升；可通过背景和边框变化表达。

## 8. 图标系统

- 全部正式图标采用同一套 1.75–2px 线性 SVG 图标。
- 常规尺寸：16px；导航：18px；独立主要操作：20px。
- 图标默认继承文字颜色。
- 图标必须有文字标签或可访问名称；不能依赖图形猜测业务含义。
- 删除现有导航、按钮和时间线中的 Emoji 与 Unicode 装饰符号。

## 9. 组件原则

### 9.1 按钮

- 每个页面或弹窗只有一个主要按钮。
- 主要按钮：陶土色实底，用于确认当前最重要动作。
- 次按钮：纸色或透明底，用于可逆操作。
- 文字按钮：用于低风险、邻近内容的轻操作。
- 危险按钮：默认不填充，最终确认阶段才使用危险色实底。
- 按钮高度：常规 40px，紧凑 32px，重要操作 44px。

### 9.2 列表

- 客户、待办和时间线优先使用连续列表，不拆成大量独立卡片。
- 选中态使用 `clay-soft` 或纸张色变化。
- 悬停只改变背景；不位移、不抬升。
- 行内操作默认后退，在悬停、选中或聚焦时增强。

### 9.3 表单

- 标签始终可见，不用 placeholder 替代标签。
- 相关字段成组，非核心字段折叠为“更多资料”。
- 错误说明靠近字段并说明如何修正。
- 保存成功明确说明结果；不只显示“成功”。

### 9.4 弹窗和面板

- 简短确认使用弹窗。
- 需要阅读上下文或连续编辑时使用侧面板或工作区。
- 弹窗背景可以有玻璃材质，正文区域保持稳定的纸张底色。
- 关闭、取消和主操作的位置在全站保持一致。

### 9.5 空状态

必须回答：这里是什么、为什么为空、下一步可以做什么。

不用庆祝式插画或 Emoji。需要插图时使用单色线稿或低饱和编辑插画。

## 10. 液态玻璃规则

液态玻璃用于表达层级，不作为装饰。

允许使用：

- 固定或浮动导航。
- 页面顶部随滚动悬浮的操作区。
- AI 助手入口和临时对话面板。
- 日期选择器、菜单、弹窗和上下文工具条。

禁止使用：

- 客户长列表、表格和时间线正文。
- 大面积页面背景。
- 输入框内部和长文本阅读区。
- 多层玻璃相互叠加。

建议参数：背景透明度 56%–78%，模糊 24–36px，适度提升玻璃内部饱和度，使用 1px 高光边缘、顶部内高光和低对比度大范围阴影。必须提供不支持 `backdrop-filter` 时的实色回退。

### 10.1 玻璃的空间职责

玻璃层必须解决空间问题，而不只是表现材质：

- 把搜索、快速记录、添加客户和 AI 等高频能力收纳为紧凑的悬浮操作架。
- 操作架随滚动保留，不占据新的整行页面区域。
- 桌面端靠近页面右上方；窄屏时移动到底部安全区，适配拇指操作。
- 默认只展示最重要动作和可识别图标，次要能力进入菜单。
- 展开后覆盖内容上方，关闭后恢复紧凑状态，不推动页面重新排版。
- 玻璃下方内容仍须可辨认，但不能影响操作文字和图标的对比度。

## 11. 动效标准

- 微交互：160–200ms。
- 面板与弹窗：220–280ms。
- 使用缓出或轻微弹簧感，不使用明显回弹。
- 位移距离通常不超过 8px。
- 列表变化应保持位置连续，避免整页刷新感。
- 支持 `prefers-reduced-motion`，关闭非必要动画。

动画服务于四件事：说明来源、确认结果、保持连续、引导注意。除此之外不添加动画。

## 12. “今天”页面模板

页面顺序固定为：

1. 日期、标题和一句工作摘要。
2. 今日明确待办列表。
3. 当前选中客户的上下文与主要动作。
4. 未来短期安排。
5. 折叠的本周记录和最近动态。

规则：

- 待办是页面主角，统计信息不能成为大卡片。
- 右侧上下文只服务于当前选中待办。
- “记录沟通”是最主要动作，“安排下一步”等动作后退。
- 逾期用文字提示，不使用红色大面积警报。
- 未来安排是轻量时间带，不在首页复制完整日历。

## 13. 修改验收清单

每次 UI 修改必须确认：

- 是否复用了已有组件和 Token？
- 是否出现了新的颜色、字号、圆角、阴影或间距？如有，理由是什么？
- 页面是否只有一个最突出的主要动作？
- 是否使用了 Emoji 或风格不一致的图标？
- 是否存在不必要的卡片、边框和状态颜色？
- 正常、悬停、聚焦、禁用、加载、空和错误状态是否完整？
- 键盘操作和焦点是否清楚？
- 1440px、1280px、960px 和窄屏布局是否可用？
- 长客户名、中英文混排和大量数据是否会破坏布局？
- 是否支持减少动态效果？
- 修改前后是否完成真实页面截图对比？
- 是否仍然符合 `PRODUCT_DESIGN_STANDARD.md` 的产品原则？

## 14. 推进方式

1. 先以独立样板确认色彩、字体、密度、材质和整体气质。
2. 将确认后的基础 Token 写入正式样式表。
3. 统一按钮、输入、导航、弹窗和列表等基础组件。
4. 首先改造“今天”，再依次改造 Inbox、客户列表、客户详情。
5. 每完成一个页面进行桌面、窄屏和关键状态视觉验收。
6. 新功能只能组合已有模式；确需新增模式时先更新本规范。

## 15. Token 架构与命名

### 15.1 三层 Token

正式样式必须采用三层结构，避免组件直接写死颜色和尺寸：

1. **原始值（Primitive）**：色阶、像素值、透明度和时间。
2. **语义值（Semantic）**：页面背景、正文、主操作、危险状态等角色。
3. **组件值（Component）**：按钮背景、导航选中态、玻璃边缘等具体用途。

示例：

```css
--color-clay-600: #A85F45;              /* 原始值 */
--color-action-primary: var(--color-clay-600); /* 语义值 */
--button-primary-bg: var(--color-action-primary); /* 组件值 */
```

组件不得直接引用原始色阶，除非该值本身就是组件的唯一视觉资产。

### 15.2 语义 Token 清单

| 类别 | Token | 说明 |
|---|---|---|
| 页面 | `--surface-canvas` | 应用最底层背景 |
| 页面 | `--surface-paper` | 主要内容背景 |
| 页面 | `--surface-raised` | 输入、菜单、实色浮层 |
| 页面 | `--surface-selected` | 列表选中与弱强调 |
| 文字 | `--text-primary` | 标题和主要正文 |
| 文字 | `--text-secondary` | 说明和次要正文 |
| 文字 | `--text-muted` | 日期、标签、系统信息 |
| 文字 | `--text-on-action` | 主操作按钮文字 |
| 边界 | `--border-subtle` | 内容分隔线 |
| 边界 | `--border-control` | 输入和普通按钮边框 |
| 边界 | `--border-focus` | 键盘与输入焦点 |
| 操作 | `--action-primary` | 主操作 |
| 操作 | `--action-primary-hover` | 主操作悬停 |
| 状态 | `--status-danger` | 错误、逾期和危险操作 |
| 状态 | `--status-success` | 已完成与成功 |
| 状态 | `--status-info` | 信息、同步和日历 |
| 状态 | `--status-waiting` | 等待和未来安排 |
| 材质 | `--glass-surface` | 标准玻璃背景 |
| 材质 | `--glass-border` | 玻璃高光边缘 |
| 材质 | `--glass-shadow` | 玻璃悬浮阴影 |

### 15.3 层级 Token

| Token | 建议值 | 用途 |
|---|---:|---|
| `--z-base` | 0 | 页面内容 |
| `--z-sticky` | 20 | 吸顶标题或筛选器 |
| `--z-command` | 40 | 悬浮操作架 |
| `--z-menu` | 60 | 下拉菜单、日期选择器 |
| `--z-overlay` | 80 | 遮罩 |
| `--z-modal` | 100 | 弹窗和工作区面板 |
| `--z-toast` | 120 | 临时反馈 |

禁止在具体组件中随意使用 999、9999 等无法管理的层级值。

## 16. 交互状态总则

所有可操作组件必须至少设计以下状态：

| 状态 | 视觉要求 | 行为要求 |
|---|---|---|
| 默认 | 清楚但不过度突出 | 可以理解用途 |
| 悬停 | 背景或边框轻微变化 | 不产生布局位移 |
| 按下 | 明度或缩放轻微变化 | 反馈不超过 100ms |
| 键盘聚焦 | 2px 清晰焦点环 | 不被阴影或容器裁切 |
| 禁用 | 降低对比并保持可辨识 | 不响应点击，说明原因时提供提示 |
| 加载 | 保持原尺寸 | 防止重复提交，文字说明正在发生什么 |
| 成功 | 短暂确认结果 | 随后回到正常层级 |
| 错误 | 危险色与文字说明 | 提供修正方法，不只显示错误代码 |

焦点环建议使用陶土色与 2px 外间距；深色或陶土色组件上使用暖白焦点环。

## 17. 基础组件详细规格

### 17.1 按钮

| 类型 | 高度 | 水平内边距 | 圆角 | 使用场景 |
|---|---:|---:|---:|---|
| 主要按钮 | 44px | 18px | 10px | 页面或弹窗的唯一核心动作 |
| 普通按钮 | 40px | 16px | 10px | 次级、可逆动作 |
| 紧凑按钮 | 32px | 12px | 8px | 表格和局部工具区 |
| 图标按钮 | 40×40px | 0 | 10px | 搜索、关闭、更多操作 |
| 文字按钮 | 自适应 | 0–4px | 6px | 邻近内容的低风险动作 |

具体要求：

- 按钮文字通常为 13–14px、600 字重。
- 主要按钮最小宽度 88px；只有图标的按钮必须有可访问名称。
- 同一操作区内按钮间距为 8px。
- 按钮文字不使用“确定”“提交”等模糊词，应写“添加客户”“记录沟通”“保存修改”。
- 加载时保留原文字宽度，可显示小型进度符号和“正在保存”。
- 禁止一个弹窗同时出现两个实心品牌色按钮。

### 17.2 输入框与文本区域

| 属性 | 输入框 | 文本区域 |
|---|---:|---:|
| 最小高度 | 42px | 112px |
| 圆角 | 10px | 12px |
| 内边距 | 0 13px | 11px 13px |
| 字号 | 15px | 15px |
| 背景 | `paper-strong` | `paper-strong` |

- 默认边框使用 `border-control`，焦点时使用品牌色边框和弱焦点光晕。
- 标签位于输入框上方，标签与控件间距 8px。
- 必填标记使用文字“必填”或可访问说明，不单独依赖红色星号。
- 帮助文字位于控件下方，间距 6px，字号 12–13px。
- 错误状态不改变控件尺寸，避免页面跳动。
- Placeholder 只能提供格式示例，不能承载重要说明。

### 17.3 选择器、日期与筛选器

- 单选和少量筛选使用分段按钮或短标签；超过 5 项使用菜单。
- 日期快捷选项只保留常用值，自定义日期进入日期选择器。
- 当前选中项同时使用背景、文字和必要的图标表达。
- 筛选器可以使用胶囊圆角，但页面主要按钮不能全部胶囊化。
- 筛选变化应保留滚动位置；结果为空时说明当前筛选条件。

### 17.4 标签与状态

| 属性 | 规格 |
|---|---|
| 高度 | 24–28px |
| 字号 | 12px |
| 字重 | 500–600 |
| 内边距 | 6–9px |
| 圆角 | 胶囊或 8px，按语义统一 |

- 国家、行业等描述性标签可以分别使用雾蓝和赭金弱背景。
- AI 建议使用苔绿弱背景，但必须带“AI 建议”文字。
- 标签不是彩色装饰；同一区域同时出现的强调色标签不超过 3 种。
- 逾期不设计成红色胶囊徽章，优先使用明确的红色文字“逾期 1 天”。

### 17.5 连续列表

- 默认行高 64–76px；包含两行内容时建议 72px。
- 左右内边距 12–16px，行间使用 1px 弱分隔线。
- 主要文本 14–15px、600；说明文字 12–13px。
- 选中行可变成独立纸张块，圆角 14px，并在上下留出 6–8px 呼吸空间。
- 行尾只展示时间、状态或一个最重要动作；更多操作进入菜单。
- 长文本单行截断，但打开详情后必须可看到完整信息。
- 列表加载时使用保持真实行高的骨架，不使用全屏转圈。

### 17.6 表格

- 只有用户需要跨行比较多个固定字段时才使用表格。
- 表头 12px、600、弱化色；正文 14px。
- 行高不低于 48px；首列通常为最重要识别信息。
- 不使用竖向网格线；通过对齐、列宽和弱横线组织信息。
- 数字右对齐，文本左对齐，日期保持一致格式。
- 窄屏下表格转换为列表或只保留关键列，不做无法阅读的横向压缩。

### 17.7 卡片和内容容器

- 卡片只用于表达一个完整、可独立理解的上下文。
- 普通内容容器圆角 16px；主要上下文或玻璃面板圆角 24px。
- 卡片内边距通常为 20–28px。
- 同一页面最多有一个视觉上明显的大型浮起卡片。
- 普通卡片不添加 hover 抬升；可点击卡片通过背景、边框和光标说明。

### 17.8 弹窗、侧面板与工作区

| 类型 | 尺寸 | 场景 |
|---|---|---|
| 确认弹窗 | 440–480px | 删除、放弃修改、单一确认 |
| 表单弹窗 | 520–680px | 添加客户、安排下一步 |
| 侧面板 | 560–760px | 需要参考当前页面的编辑 |
| 客户工作区 | 900–1120px | 时间线、资料和联系人综合查看 |

- 标题区、正文区、操作区职责固定。
- 操作区右侧放主要动作，左侧或其左边放取消。
- 关闭按钮固定在右上角，点击遮罩是否关闭取决于数据是否可丢失。
- 有未保存修改时，关闭必须进入明确的保留/放弃流程。
- 正文很长时只滚动正文区，标题和操作区保持可见。

### 17.9 Toast 与页面反馈

- 成功 Toast 显示 3–4 秒，错误 Toast 保留到用户关闭或问题解决。
- 位置优先在右下角，避开 AI 和底部操作架。
- Toast 必须说明结果，例如“客户已归档，可以在设置中恢复”。
- 对于页面内容已经明显变化的操作，不重复显示无价值的“成功”。
- 需要用户处理的问题使用页面内反馈，不把重要错误藏在短暂 Toast 中。

### 17.10 加载、空状态和错误状态

- 首次进入页面可使用结构骨架；局部刷新只加载对应区域。
- 空状态正文不超过两句，只提供一个主要下一步。
- 网络或服务错误必须保留已加载内容，允许重试。
- 无数据与加载失败必须有不同文案和视觉。
- 不使用 Emoji、庆祝插画或大面积彩色插画填充空状态。

## 18. 悬浮玻璃操作架（Command Shelf）

这是 Trade OS 表达 Apple 空间语言的核心组件，不是普通工具栏。

### 18.1 默认结构

桌面端从左到右建议为：

1. 搜索图标。
2. 当前页面的唯一主要动作。
3. 添加或更多操作图标。

“今天”页面的默认主要动作是“记录沟通”。其他页面可根据职责替换，但整个操作架只能有一个实心按钮。

### 18.2 尺寸与材质

| 属性 | 桌面端 | 窄屏 |
|---|---:|---:|
| 总高度 | 50–54px | 52–56px |
| 外边距 | 顶部 20–24px，右侧 28–40px | 底部安全区 12–20px |
| 内边距 | 5–6px | 5–6px |
| 圆角 | 16–18px | 18–22px |
| 模糊 | 28–36px | 28–36px |
| 背景透明度 | 56%–72% | 62%–78% |

玻璃必须具有顶部高光、半透明边缘和柔和投影。文字对比不足时增加局部实色衬底，而不是继续降低透明度。

### 18.3 滚动行为

- 页面顶部时与标题区自然对齐。
- 向下滚动后保持悬浮，可以缩短文字但不能隐藏主要动作。
- 展开搜索或菜单时在当前层级覆盖内容，不改变主页面布局。
- 滚动方向不用于自动隐藏操作架，避免重要能力忽隐忽现。
- 移动端操作架固定在底部安全区，不能遮挡最后一项内容；页面底部必须预留空间。

### 18.4 可用性边界

- 操作架最多容纳 4 个直接操作。
- 图标必须来自统一图标系统。
- 危险操作不得直接放在操作架上。
- 页面不存在明确主要动作时，可只保留搜索与 AI，不强行放置品牌色按钮。
- 用户滚动阅读长内容时，操作架保持低干扰，不播放材质动画。

## 19. 导航系统

### 19.1 桌面侧栏

- 展开宽度：216–232px；紧凑宽度：76–84px。
- 与窗口边缘保持 16–20px 外间距，使用 24px 玻璃圆角。
- 品牌区在顶部，账号与设置固定在底部，主导航占据中部。
- 一级导航只保留高频的“今天、Inbox、客户”；新客户、完整日历、全部记录和操作日志进入可展开的“更多工具”，功能入口继续完整保留。
- 导航行高 44px，左右内边距 12px，图标 18px。
- 当前页面使用纸张色块和弱阴影，不使用高饱和整行背景。
- 未选中项目保持足够对比度，不能因追求玻璃效果而变灰到难以识别。

### 19.2 紧凑侧栏

- 只显示图标和必要计数，悬停或键盘聚焦时显示名称提示。
- 当前页面仍通过背景形状和图标颜色共同表达。
- 计数徽章放在图标右上侧，不改变导航项对齐。

### 19.3 移动导航

- 小于 720px 时使用抽屉或底部导航，最终形式在移动端样板中确认。
- 若使用底部导航，只保留“今天、Inbox、客户”三个一级入口。
- 设置、账号和低频能力进入菜单。
- 移动导航与 Command Shelf 不能互相遮挡或重复提供同一动作。

## 20. 页面模板细化

### 20.1 通用页面骨架

所有一级页面遵循：

1. 日期或上下文眉题。
2. 页面标题。
3. 一句话说明当前页面需要用户理解或完成什么。
4. 主内容。
5. 次级内容或折叠区。
6. 悬浮 Command Shelf。

页面标题区不放大面积统计卡，操作优先进入 Command Shelf。

### 20.2 Inbox

- 主体是待判断信号列表，不是通知流。
- 顶部可以有简洁筛选，但不显示多个彩色统计卡。
- 信号详情继续保留“安排下一步、记录最新进展、暂不安排下一步、查看分析”等现有处理方向，处理后提供撤销。
- AI 信号使用苔绿弱背景和明确来源；客户回复使用纸张层。
- 已处理信号离开当前列表时使用轻微收起动画并提供撤销。

### 20.3 客户列表

- 搜索是首要入口，标签和动态视图是辅助入口。
- 默认连续列表或克制表格，不使用客户卡片墙。
- 每行优先展示公司、国家/行业、最近发生和明确下一步。
- “等待回复”“很久未联系”等是动态视图，不表现为需要维护的彩色状态。
- “未获回复”和“已有联系”作为一级动态视图：只有客户回复开发信，或记录为客户来信/双向沟通时进入已有联系；已发送开发信和我方单向跟进归入未获回复。该分类由实际活动动态计算，无需手动维护。
- 批量操作只有用户主动选择多项后出现。

### 20.4 客户详情

- 客户名称、联系人与关键资料建立身份区。
- 时间线是主体，资料、联系人和 AI 分析按需展开。
- 事实、下一步和 AI 建议使用不同的版式角色，而不是只换颜色。
- 记录沟通是最常用动作；安排下一步是独立动作。
- 长报告使用稳定纸张层，限制行宽，不使用玻璃背景。

### 20.5 本周工作

- 保持三人内容并列的产品原则，宽屏三栏、窄屏单列。
- 不增加 KPI、排名、彩色统计和仪表盘图表。
- 每条内容突出公司、事实、结果和下一步。
- 色彩用于区分内容层次，不用于区分人员绩效。

### 20.6 设置

- 按主题分组：账户、数据、同步、AI、维护。
- 危险维护区放在页面末尾，并与普通设置保持明显间隔。
- 技术信息默认折叠，面向用户的说明使用普通业务语言。
- 保存即时生效的设置应原地反馈；需要重新启动时提前说明。

## 21. 可读性与无障碍

### 21.1 对比度

- 正文与背景对比度必须达到 WCAG AA：普通文字至少 4.5:1，大文字至少 3:1。
- 次级文字也不能低于最低阅读标准；低对比只用于非必要装饰。
- 玻璃上的文字必须按其最复杂背景进行验证。
- 焦点、错误和选中不能只用颜色表达。

### 21.2 点击与键盘

- 鼠标点击目标不小于 36×36px；移动触控目标不小于 44×44px。
- 所有功能必须可以通过键盘完成。
- Tab 顺序与视觉顺序一致。
- 弹窗打开后焦点进入弹窗，关闭后返回原触发位置。
- Escape 仅关闭不会导致数据丢失的临时浮层。

### 21.3 缩放与系统设置

- 浏览器放大到 200% 时核心操作仍可完成。
- 支持系统减少动态效果。
- 不依赖鼠标悬停才能看到必需信息。
- 文本不能嵌入位图；图标提供可访问名称。

## 22. 内容呈现细节

### 22.1 日期与时间

- 中文日期默认使用“2026 年 7 月 15 日”或“7 月 15 日”。
- 相对时间只用于近期内容，并在详情中提供准确日期。
- “逾期 1 天”“今天”“明天”优先于难以快速判断的纯日期。
- 同一页面不混用多种日期格式。

### 22.2 数字与统计

- 数字使用等宽数字特性，避免列表刷新时抖动。
- 统计只为帮助决策而出现，不以大卡片占据首屏。
- 0 值通常不需要强调；异常数字必须带解释。
- 不以红色数字制造没有行动意义的压力。

### 22.3 长名称与多语言

- 公司名称默认单行截断，详情中完整显示。
- 中英文之间由字体系统自然调整，不手动加入多余空格。
- 邮箱、网址和长编号允许安全换行或中间省略。
- 界面布局不能依赖固定字符数量。

### 22.4 AI 内容

- 所有 AI 内容必须标注“AI 建议”或“AI 分析”。
- 事实依据优先显示，建议使用苔绿弱背景或独立编辑区。
- AI 操作入口可以使用玻璃层，AI 长文本必须回到纸张层。
- AI 生成过程中说明正在分析什么；失败时保留用户输入。

## 23. 动效模式明细

| 场景 | 时长 | 位移/变化 | 说明 |
|---|---:|---|---|
| 按钮悬停 | 160ms | 背景和边框 | 不位移 |
| 列表选中 | 180–220ms | 背景、圆角、弱阴影 | 保持行位置连续 |
| 菜单出现 | 180–220ms | 透明度 + 4px | 从触发位置出现 |
| 弹窗进入 | 220–260ms | 透明度 + 6px | 不明显缩放 |
| 侧面板进入 | 240–280ms | 8px 横向位移 | 不推动主内容 |
| Toast | 180–220ms | 透明度 + 4px | 离开时更快 |
| 列表项完成 | 200–260ms | 收起高度 + 淡出 | 提供撤销时保留位置 |

液态材质不做持续流动、光斑追随或鼠标跟随。所谓“动态玻璃”主要来自滚动内容穿过玻璃后的真实材质变化，而不是额外特效。

## 24. 视觉验收矩阵

### 24.1 必测窗口

| 场景 | 建议尺寸 |
|---|---|
| 大桌面 | 1440×900 或更大 |
| 普通笔记本 | 1280×800 |
| 窄桌面窗口 | 960×760 |
| 平板/窄屏 | 768×1024 |
| 手机 | 390×844 |

### 24.2 必测数据状态

- 初次使用、完全空白。
- 正常数量数据。
- 20 条以上列表。
- 超长中英文客户名。
- 没有联系人或没有下一步。
- 多项逾期。
- 加载中、局部失败和完整失败。
- 权限不足、禁用操作和未配置 AI。
- 弹窗有未保存内容。

### 24.3 截图要求

- 每次正式页面视觉修改保留修改前后截图。
- 截图使用相同窗口尺寸、数据和滚动位置。
- 至少检查默认、选中、空状态和一个弹窗。
- 视觉差异需要解释是预期改变还是回归问题。

## 25. 规范的变更方式

### 25.1 版本规则

- 文案澄清、轻微参数调整：补丁版本，例如 v1.0.1。
- 新组件、新页面模式或辅助色：次版本，例如 v1.1。
- 核心视觉方向、导航或布局原则改变：主版本，例如 v2.0。

### 25.2 新想法如何进入规范

每个新想法先回答：

1. 它解决了什么真实使用问题？
2. 它属于纸张、墨迹还是玻璃层？
3. 现有组件为何不能承载？
4. 是否增加了新的颜色、尺寸或交互模式？
5. 在窄屏、键盘和长数据情况下是否仍然成立？
6. 是否会让产品更花哨、更科技化或更难阅读？

通过后先更新独立样板，再更新规范，最后才进入正式页面。

### 25.3 当前已经认可的方向

- 暖质编辑式工作台作为核心视觉命题。
- 温暖纸张色与陶土色作为主色基础。
- 增加苔绿、雾蓝、赭金等低饱和辅助色，避免单调。
- 保留当前 10/16/24px 为主的圆角体系。
- 标题使用适度编辑式衬线字体，正文使用清晰系统字体。
- 正文与辅助字号相比第一版略微增大，提高阅读清晰度。
- 页面信息密度偏宽松，允许自然滚动。
- 完全取消 Emoji，统一线性图标。
- 液态玻璃承担导航、悬浮操作和临时上下文，不承载长内容。
- Command Shelf 始终保留最重要操作，同时减少固定工具栏占用。
- 页面保持整洁，不走鲜艳、赛博或传统企业后台方向。

### 25.4 后续实施决定

- 字体以美观度为优先，中文展示字体采用本地托管方案；正式文件在 Windows 实页对比后冻结。
- 辅助色在不同页面中的具体使用比例。
- iPad 保留完整核心操作；iPhone 以查看、搜索和阅读为主，不为复杂编辑单独重构流程。
- Command Shelf 展开搜索和 AI 时的详细交互。
- 深色模式不进入当前优化阶段。
- 客户详情采用快速工作区与完整详情结合的响应式方案。
- 插图是否需要建立专门的日式编辑线稿风格。

辅助色比例、Command Shelf 展开方式和插图风格继续通过逐页样板确认，不阻碍 v1.0 分阶段实施。
