# 房间文档（rooms）

一个页面一份 `rooms/<页面>.md`，例如 `customer.md`、`today.md`、`inbox.md`、`search.md`。

**它是怎么产生的**：先在 `design/visual-exploration/` 做几个独立 HTML 原型，由人选定其一，再从被选中的原型提炼成这里的文档，最后才实现。规范跟着原型走，不先写规范再画页面。流程与世界规则见 [`../DESIGN_WORLD.md`](../DESIGN_WORLD.md)。

**边界**：房间可以在空间模型、隐喻、构图、招牌交互上自由发挥；但不得引入新材质（新色系、新字体家族、玻璃、重阴影），也不得放松 [`../UI_QUALITY_BASELINE.md`](../UI_QUALITY_BASELINE.md) 的底线。

目前还没有房间文档，选定第一个原型后再添加。

## 模板

复制下面的结构，每节保持简短；没有内容的节写“无”，不要删除。

```markdown
# 房间：<页面名>

- 来源原型：design/visual-exploration/<...>/<file>.html（选定日期、选定人）
- 状态：探索 | 已选定 | 已实现（对应 commit / release）

## 隐喻
一句话：这个房间像什么。

## 动词
用户在这里做的 1–3 件事（如：恢复上下文、记录事实、确认下一步）。
高频动词写出最快路径的步数。

## 空间模型
构图：焦点在哪里、周边放什么、光落在哪里；桌面 / iPad / 手机三种排布。

## 招牌交互
一个。说明触发、反馈、键盘等价路径、触屏等价路径、减少动态下的表现。

## 意外细节
一个“意料之外但有用”的细节，以及它帮用户省掉了什么。

## 数据来源 / 接口
每块内容来自哪个现有 API / service（不得直接读写数据库或用 UI 读业务数据）；
哪些是 AI 预填内容，如何标注“AI 建议 / AI 分析”；不新增写入语义。

## 状态
加载、空、未登录、权限、网络、服务、解析错误，各自在此房间里如何呈现；
“没有数据”与“加载失败”如何区分。

## 禁忌
本房间的默认不做项，每条带理由（“默认不做，理由是……”）。
如有突破世界默认（DESIGN_WORLD.md 1.8）的地方，在此写明并说明为什么值得。

## 验收
- 缩略图测试：与其他房间并排时的可辨识点
- 去 logo 自检结论
- 真实浏览器矩阵：宽屏 / iPad / iPhone / 旧 Win10 / 键盘 / 200% 缩放 / 性能模式
- 数据状态：空白、20+ 条、超长名称、无联系人 / 无下一步、多项逾期、失败态
- 回归：客户、联系人、沟通记录、Today、Inbox、Search、备份恢复、Sela 幂等同步未受影响
```
