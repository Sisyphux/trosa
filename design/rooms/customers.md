# 房间：客户列表

- 来源原型：`../visual-exploration/rooms-v5/customers/03-ledger.html`（2026-09-30 选定；选定人：用户）
- 状态：已实现于分支 `agent/room-customers-impl-0930`（任务 `room-customers-impl-0930`），未发布；实现与原型的差异见文末「实现记录」。

## 隐喻
一本按时间往下记的账本长卷。找人靠「节奏与对齐」：公司名靠左、时间靠右，中间一条点线引过去。

## 动词
找到那个客户并恢复上下文：
- 凭大致位置快速到达（招牌动作：拖尺速览，1 步）。
- 打开客户（选中条目 → 「打开 ↵」，1–2 步）。
- 切换动态视图 / 搜索（各 1 步）。

## 空间模型
- 纵向一条连续长卷：左边距是「书眉」（当前分段本周/本月/… 与小计随滚动更换），正文是等高条目，右边一条刻度尺（Canvas 画整卷刻度）。
- 条目两行：第一行公司名靠左、时间靠右、中间点线引导；第二行三段固定列（国家·行业 | 最近发生 | 下一步），纵向对齐。
- 选中条目（悬停或键盘）被金色薄雾照亮、文字转墨色，其余低对比；整页唯一实心「打开 ↵」只出现在这一条上，窄屏（≤900px）移到底部栏。
- 桌面一栏 + 右侧刻度尺；窄屏刻度尺缩到 26px，条目第二行只留「国家·行业」与「下一步」，底部栏补一句。

## 招牌交互
拖尺速览：按住右侧刻度尺拖动，整卷随之滚动；金色竖条标出当前可视窗口，刻度尺用不同长度表达紧迫度（逾期长红刻度、已排期中刻度、无下一步短淡刻度、分段起点金线）。悬停显示浮签（公司 + 国家 + 距今）。1000 条里也能凭大致位置一秒到达。键盘等价：方向键逐条移动（`aria-activedescendant`），`Enter` 打开。触屏等价：拖动刻度尺（手感未实测，见验收）。减少动态下过渡瞬时到终态。

## 意外细节
分段「结转」小计：每个时间分段开头像账本结转行，写 `29 家 · 逾期 2 · 等待回复 6 · 尚无下一步 9 · 很久未联系 …`；书眉里同一份小计随滚动跟随。往下读之前就知道这一段哪里堆积了麻烦，省掉逐条数。

## 数据来源 / 接口
- 列表：`GET /api/customers?view=&search=&page=&per_page=`，已返回 `company/name/country/field|industry/last_contact/latest_outreach_date/has_contact/waiting_reply/days_since_contact/next_task_title/next_task_date/website/match_reasons`。
- 动态视图（全部 / 未获回复 / 已有联系 / 等待回复 / 很久未联系 / 尚无下一步）由 `has_contact / waiting_reply / days_since_contact / next_task_date` 计算，不手动维护；视图数字是当前搜索下的命中数。
- 全部为现有接口，无 AI 预填内容。

## 落地前要补的缺口
- **每个视图的数量（后端）**：现有响应只返回当前视图的 `total`；需要一个便宜的服务端计数，或在同一响应里带 `counts`。
- **分段「结转」小计（后端）**：需服务端按 `days_since_event` 分桶计数，否则小计只对已加载页有效。
- **刻度尺数据（后端）**：需要总条数与每条的紧迫度分类；建议服务端返回轻量索引（`id + 距今天数 + 逾期/无下一步标志`），点到某位置再按页取详情。
- **「此刻可联系」按时区筛选（后端，本期不做）**：依赖尚不存在的客户时区，见「禁忌 / 后续」。
- 以上均属**读**能力补充（计数 / 聚合 / 索引），不新增写入语义。
- **分段口径（已定）**：按「最近发生」分段（今天 / 昨天 / 本周…），贴近「先看谁刚有动静」；「结转」小计仍按 `days_since_event` 分桶。

## 状态
- 加载：台账占位行（短横条 + 点线），`role=status` 的「正在读取客户…」。
- 空：一页只有横格线的空白纸 + 唯一实心「添加客户」。
- 失败：一条红线引出的「划掉」条 + 错误说明 + 「重新加载」；不画成「没有数据」。
- 无搜索结果：查询词被金线划掉，并给拼写建议；与「空客户列表」区分。
- 未登录 / 权限 / 解析错误：原型未画；实现沿用现有页面的区分。
- 「没有数据」与「加载失败」用不同文案与画法区分。

## 禁忌
- 默认不做：「此刻可联系」按时区筛选。理由：本期不做，依赖尚不存在的客户时区（见缺口）；把它留作后续。
- 默认不做：批量管理作为默认负担。理由：批量只在用户主动选入后出现（底部托盘），不选则无批量入口。
- 默认不做：超长公司名换行撑高条目。理由：定高条目内单行截断，并提供 `title` / 详情里完整显示。
- 默认不做：把客户等级放回前台。理由：等级仅历史数据，不再作为前台负担。
- 未选其它方向（一两句）：01 卡柜（横向纵深、竖排文字，扫读慢）与 02 时区光带（更像 Today 的答案，放列表需额外论证）。用户选定 03 台账——最稳、最快扫读、最易落地；落选方向的细节见其原型 README，本文不复制。
- 突破世界默认处：无。

## 验收
- 缩略图测试：与其它房间并排时应可辨为「一张长纸 + 点线引导 + 右侧刻度尺」。
- 去 logo 自检：本方向最像普通列表，需靠衬线、点线引导、书眉与刻度尺保持可辨。
- 真实浏览器矩阵（**均未验证**）：宽屏 1440×900 / 1280×800 / 960×760 / 390×844、iPad 真机触控、iPhone 真机、Safari、旧 Win10、键盘全流程、200% 缩放、系统级减少动态、性能模式。
- 数据状态：空白、20+、1500 条（`?n=1500`）、超长中英文公司名、无联系人或无下一步、多项逾期、失败态、无搜索结果。
- 焦点环：房间内统一 `2px solid var(--dl-focus)`，外移 3px；`--dl-focus` 即 `--dl-gold-ink`，纸面对比度 ≥3:1（`tools/check_daylight_contrast.py` 通过）。亮金 `#bc9052`（2.85:1）只作装饰，不作焦点环。
- 回归：客户、联系人、沟通记录、Today、Inbox、Search、备份恢复、Sela 幂等同步未受影响。
- 性能：定高窗口化（约 18 节点）与刻度尺 Canvas（1500 条画约 700 根刻度）在中低端设备上的帧率与内存。

## 实现记录（room-customers-impl-0930）

- **接口（只读，不改数据模型）**：`GET /api/customers/ledger?view=&search=…` 返回 `counts`（六个视图数量，随搜索/筛选变化、不随所选视图变化）、`segments`（按最近发生分桶的小计：今天 / 昨天 / 本周 / 本月 / 一至三个月 / 更早 / 尚无记录，含逾期、等待回复、尚无下一步、很久未联系）与刻度尺索引 `index: [[id, 距今天数, 标志位], …]`；`GET /api/customers/ledger/rows?ids=…&search=…`（≤100 个）返回窗口内的白名单字段行。两者复用 `GET /api/customers` 同一份事实投影（`_customer_list_payload`），视图定义与旧列表逐项一致；最近发生取沟通与开发邮件中较新的一个日期。
- **标志位**：1 逾期 · 2 尚无下一步 · 4 等待回复 · 8 很久未联系 · 16 已有联系；刻度尺据此画长短。
- **窗口化**：定高条目（桌面 4.7rem，窄屏 6rem），滚动时只渲染可视区上下各约 420px 的条目，行详情按每 50 位一块读取并缓存；1500 条时 DOM 约 15–21 个节点。
- **保留的旧入口**：手动排序与已归档两个视图仍用原有列表（拖拽排序与恢复归档依赖它）；「更多筛选」「保存当前视图」沿用原面板并挪进台账；单个客户的归档保留为选中行上的文字动作「归档」（键盘 Delete / Backspace），仍走原有确认与可恢复流程。
- **与原型的有意差异**：① 不做批量选入托盘（本期禁止新增批量入口；旧的批量导出邮箱 / 批量归档只在手动排序与已归档视图里可用）；② 「无搜索结果」暂不给拼写建议（需要额外的公司名读接口）；③ 「此刻可联系」时区筛选不做（依赖尚不存在的客户时区）；④ 搜索框沿用页面全局搜索的取值（房间内的输入框与它同步）；⑤ 视图键 1–6 与 Delete 只在列表获得焦点时生效，`/` 仍属全局搜索召出层。
- **焦点环**：房间内统一 `2px solid var(--dl-focus)`，外移 3px；`--dl-focus` 即 `--dl-gold-ink`，纸面对比度 ≥ 3:1（`tools/check_daylight_contrast.py` 通过）。
- **验收状态**：真实浏览器已验证 1440×900、1024×768、390×844、720×450（等效 200% 缩放）、性能模式（无闪烁动画、无过渡、非平滑滚动）、键盘流程（搜索 → 列表 → 方向键 → Enter 打开 → Esc 返回、数字键切视图、Delete 归档）、空白 / 60 条 / 1500 条 / 超长公司名 / 无联系人与无下一步 / 多项逾期 / 失败（网络、服务、权限、解析）/ 无搜索结果。未验证：iPad 与 iPhone 真机触控、Safari、旧 Win10 浏览器、系统级「减少动态」开关（仅验证了同一分支的性能模式与样式规则）、屏幕阅读器。
